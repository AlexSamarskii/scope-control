# Публичный состав для GitHub

Публичные файлы:

- `mainapp/`, `usermodel/`, `project/`, `speedpycom/`, `crispy_tailwind/`, `demoapp/` — код и синтетические тесты;
- `templates/` и `static/` — интерфейс и ресурсы;
- `manage.py`, `docker-compose.yml`, manifests и lock-файлы;
- `README.md`, `LICENSE.md`, `LICENSE-SpeedPy.md`, `NOTICE.md`, `.gitignore` и выбранные файлы `docs/`.

Новые корневые пути игнорируются по умолчанию. Внутренние планы/отчёты,
агентские каталоги, рабочие копии доноров и локальные настройки сохраняются
на диске и не входят в публичный состав. Внутри приложения также исключены
окружения, зависимости, базы, логи, пользовательские файлы, отчёты и ключи.
Файлы `.env` и `.env.*`, включая examples, не публикуются; параметры задаются
окружением по инструкции в [README](../README.md).

## Отдельный репозиторий

Git-корень должен совпадать с каталогом Scope Control, чтобы в репозиторий
не попали история и файлы соседних проектов. Текущая структура уже использует
отдельный репозиторий. Подготовка публичного состава сама по себе
не меняет Git-индекс, не создаёт коммит и не выполняет push.

Следующие команды выполняются оператором из корня Scope Control. Если там
уже есть собственный репозиторий, повторная инициализация не нужна:

```sh
git rev-parse --show-toplevel
# Если указан родительский каталог, создать отдельный локальный репозиторий:
git init -b main
git rev-parse --show-toplevel
```

Перед добавлением файлов убедитесь, что последняя команда показывает именно
корень Scope Control. Затем проверьте состав без изменения индекса:

```sh
git status --short --untracked-files=all -- .
git add --dry-run -- .
git ls-files -- .
```

`.gitignore` применяется к новым файлам; он не удаляет уже отслеживаемые
файлы из индекса или старых коммитов. При подготовке исходного workspace
отслеживаемых файлов Scope Control не было. После создания отдельного
репозитория повторно проверьте это условие перед первым коммитом.

Сохраните [лицензию Scope Control](../LICENSE.md), [сторонние лицензии и уведомления](../NOTICE.md), оба lock-файла и тесты.
Не используйте `git add -f` для обхода исключений. Обычный ZIP всего рабочего
каталога и загрузка через браузер GitHub не учитывают `.gitignore`.

Создание GitHub-репозитория, выбор владельца/адреса remote, коммит и push —
отдельные действия. Для публикации используйте пустой репозиторий и проверенный
состав самостоятельного проекта.

## Локальная проверка после клонирования

Для запуска достаточно публичных файлов и внешних PostgreSQL/Redis;
внутренние агентские артефакты и исходники доноров не нужны.
Установка и команды тестирования находятся в [README](../README.md).
Публикация исходников не означает production-развёртывание, прохождение
live-проверок модели или пользовательского пилота.
